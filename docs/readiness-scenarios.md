# Readiness Scenarios

Wardkeep scenarios are temporary, deterministic comparisons of the household
records currently on file and a set of changes the household enters explicitly.
They are not predictions, financial recommendations, market forecasts, or
advice. A scenario is never saved, never changes the household record, and
never creates a readiness-history snapshot.

## First release contract

The first release accepts only explicit hypothetical readiness-factor changes.
Each change identifies an existing capability, states whether the household is
removing or replacing a recorded signal, and includes the exact
summary and magnitude used for the comparison. Wardkeep will show every
hypothetical input beside the current evidence.

The server will:

1. Derive the current readiness response using the normal evidence pipeline.
2. Apply only the requested in-memory signal changes.
3. Recompute affected pillar assessments, the direct overall assessment, and
   derived Peace with the current scoring contract.
4. Return current and scenario assessments, changed factors, and limitations.

The response will explicitly state when an adjustment cannot establish a score
because the affected pillar remains unevaluated or partial.

## Deliberate exclusions

- No projected income, job loss, market-price, property-value, or insurance
  outcome is generated by Wardkeep.
- No broad "buy a house" or "lose a job" preset appears until it can name the
  exact user-entered records and assumptions it changes.
- No scenario is persisted, scheduled, added to recommendations, or treated as
  an observed readiness change.
- No scenario transfers money, alters accounts, modifies obligations, or
  changes trusted access.

## Future extensions

After the first release is proven, a household may use structured builders for
cash-reserve, recorded recurring-obligation, and debt-minimum changes. Every
builder must translate to the same explicit signal-change contract and state
its evidence and limitations before a result is shown.
